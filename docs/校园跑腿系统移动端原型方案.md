# 校园跑腿系统移动端原型方案（V1）

## 1. 项目目标

设计一款面向校园场景的跑腿系统移动端原型，覆盖下单、支付、履约、完成的核心闭环，满足课程展示或产品初评需求。

V1 目标：
- 快速完成可演示原型；
- 支持最小可行支付能力；
- 明确后续可扩展方向。

---

## 2. V1 功能范围

### 2.1 服务类型（仅保留 3 项）
- 帮取快递
- 帮买商品
- 万能跑腿（自定义需求）

### 2.2 角色端
- 用户端（下单人）
- 跑腿员端（接单人）

说明：管理后台暂不纳入本次原型范围。

## 3. 最简单支付方案

## 3.1 推荐方案
仅接入 **微信支付**（移动端 JSAPI/H5 思路），不接支付宝和银行卡。

### 3.2 选择理由
- 校园用户微信覆盖率高；
- 对接一个渠道，开发和联调成本最低；
- 原型阶段可先模拟支付成功/失败，不依赖真实资金流。

### 3.3 支付流程（原型版）
1. 用户提交订单；
2. 进入收银台；
3. 选择微信支付（唯一选项）；
4. 支付成功：订单进入“待接单/进行中”；
5. 支付失败或取消：订单回到“待支付”，支持重新支付。

## 6. 核心流程设计

### 6.1 流程 A：下单支付（主链路）
首页 -> 选择服务 -> 填写需求 -> 确认订单 -> 收银台 -> 支付成功 -> 订单详情

### 6.2 流程 B：支付失败回退
收银台 -> 支付失败/取消 -> 支付失败页 -> 返回待支付订单 -> 重新支付

### 6.3 流程 C：订单履约
待接单 -> 已接单 -> 配送中 -> 已送达 -> 已完成

## 7. 页面线框文案（关键页）

### 7.1 U06 确认订单
- 标题：确认订单
- 模块：配送信息、费用明细
- 金额：跑腿费、商品预估、加价费（可选）、实付金额
- 主按钮：提交并支付
- 底部提示：提交即表示同意《跑腿服务协议》

### 7.2 U07 收银台
- 标题：收银台
- 信息：订单号、支付金额
- 支付方式：微信支付（默认勾选且唯一）
- 主按钮：立即支付
- 次按钮：取消支付

### 7.3 U08 支付成功
- 标题：支付成功
- 文案：订单已支付，等待跑腿员接单
- 按钮：查看订单、返回首页

### 7.4 U09 支付失败
- 标题：支付未完成
- 文案：本次支付未成功，请重新支付
- 按钮：重新支付、返回订单

## 9. 文案规范（统一标准）

### 9.1 按钮文案
- 主按钮采用“动词 + 结果”：提交并支付、立即支付、确认送达
- 次按钮采用“返回/取消”：取消支付、返回订单

### 9.2 状态文案
- 待支付：请在 15 分钟内完成支付
- 待接单：已支付，正在匹配跑腿员
- 已接单：跑腿员正在前往取货点
- 配送中：物品已取到，正在配送
- 已完成：订单已送达，欢迎评价

### 9.3 错误提示
- 请填写取件码
- 请填写送达地址
- 手机号格式不正确
- 网络开小差了，请稍后重试
- 支付超时，订单已恢复为待支付

## 10. 组件与视觉建议（低保真适用）

- 按钮：主按钮实心，次按钮描边；
- 标签色：待支付（橙）、待接单（蓝）、配送中（紫）、已完成（绿）、已取消（灰）；
- 订单卡片层级：
  - 第一行：订单类型 + 状态标签
  - 第二行：起点 -> 终点
  - 第三行：下单时间 + 实付金额
  - 右下角：操作按钮（最多 2 个）

## 11. 原型制作建议（Figma）

- 画板建议：iPhone 13/14（390x844）；
- 先低保真灰模，再补视觉层；

- 页面命名使用编号前缀（Uxx/Rxx）便于评审讲解。

## 12. 原型完成自检清单

- 是否存在完整支付闭环（成功、失败、重试）；
- 列表和详情中的订单状态是否一致；
- 每个关键页面是否有明确主动作按钮；
- 关键动作后是否有反馈页（成功/失败/加载）；
- 跑腿员履约链路是否可完整演示。

## 14. 技术架构（Python + FastAPI + Vue）

### 14.1 总体架构
- 前端：`Vue 3`（建议 `Vite` + `TypeScript`）
- 后端：`Python FastAPI`
- 数据库：`MySQL 8.x`（运行于 `Docker` 容器）
- 缓存：`Redis`（验证码、会话、限流）
- 对象存储：用于凭证图片（可后续接入）

### 14.2 端到端职责
- `Vue`：页面渲染、状态管理、接口调用、支付发起与结果回跳处理
- `FastAPI`：认证、订单、支付、跑腿员接单履约、消息通知接口
- `MySQL`：用户、订单、支付单、履约轨迹等核心业务数据存储
- `Redis`：短信验证码、短时状态缓存、简单防刷

### 14.3 后端模块建议（FastAPI）
- `app/api`：路由层（用户、订单、支付、跑腿员、消息）
- `app/services`：业务服务层（下单、计费、状态流转、支付回调处理）
- `app/models`：数据模型（SQLAlchemy）
- `app/schemas`：请求/响应模型（Pydantic）
- `app/core`：配置、日志、鉴权、中间件

### 14.4 前端模块建议（Vue）
- `src/views/user`：用户端页面（U01~U15）
- `src/views/runner`：跑腿员端页面（R01~R06）
- `src/router`：路由与权限控制
- `src/stores`：状态管理（Pinia）
- `src/api`：接口封装（Axios）
- `src/components`：复用组件（按钮、卡片、状态标签）

### 14.5 最小接口清单（V1）
- 认证：
  - `POST /api/v1/auth/send-code` 发送验证码
  - `POST /api/v1/auth/login` 登录注册
- 订单：
  - `POST /api/v1/orders` 创建订单
  - `GET /api/v1/orders` 订单列表
  - `GET /api/v1/orders/{id}` 订单详情
  - `POST /api/v1/orders/{id}/cancel` 取消订单
- 支付（微信）：
  - `POST /api/v1/payments/create` 创建支付单
  - `GET /api/v1/payments/{order_id}/status` 查询支付状态
  - `POST /api/v1/payments/wechat/callback` 支付回调
- 跑腿员：
  - `GET /api/v1/runner/orders/hall` 接单大厅
  - `POST /api/v1/runner/orders/{id}/accept` 确认接单
  - `POST /api/v1/runner/orders/{id}/delivered` 确认送达

### 14.6 部署建议（简版）
- 前端：`Nginx` 托管 `Vue` 静态资源
- 后端：`Uvicorn/Gunicorn + FastAPI`
- 数据库：`MySQL` Docker 容器
- 缓存：`Redis` 独立实例

### 14.7 MySQL Docker 开发配置
- 数据库镜像：`mysql:8.0`
- 容器名建议：`gofer-mysql`
- 端口映射：`3306:3306`
- Root 密码：`root123456`
- 默认字符集：`utf8mb4`

示例启动命令：
`docker run -d --name gofer-mysql -p 3306:3306 -e MYSQL_ROOT_PASSWORD=root123456 -e MYSQL_DATABASE=gofer -e TZ=Asia/Shanghai mysql:8.0 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci`

后端连接串示例：
`mysql+pymysql://root:root123456@127.0.0.1:3306/gofer?charset=utf8mb4`
