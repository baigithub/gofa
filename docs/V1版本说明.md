# 校园跑腿系统 V1 版本说明

版本：V1  
日期：2026-04-23

## 1. 版本定位

V1 目标是交付一个可完整演示的校园跑腿双端原型，覆盖“下单 -> 支付 -> 履约 -> 完成”主链路，并具备关键失败分支处理能力。

## 2. V1 已完成项

### 2.1 前端（Vue 3 + Element Plus）

- 已完成用户端 `U01-U15` 全页面
- 已完成跑腿员端 `R01-R06` 全页面
- 已完成移动端科技风统一视觉与组件化改造
- 已完成关键流程跳转：
  - 下单 -> 确认订单 -> 收银台 -> 支付结果
  - 支付失败 -> 返回待支付 -> 重试
  - 跑腿员接单 -> 配送 -> 完成
- 已完成状态管理、路由权限、统一 API 错误处理
- 已完成 loading/empty/error 状态覆盖（重点页面）

### 2.2 后端（FastAPI）

- 已完成认证接口：发送验证码、登录
- 已完成订单接口：创建、列表、详情、取消
- 已完成支付接口：创建支付单、查询状态、微信回调
- 已完成跑腿员接口：大厅、接单、送达
- 已完成订单状态机、统一响应结构、错误码、基础日志与请求追踪
- 已完成 OpenAPI 文档与示例补充

### 2.3 基础设施与联调

- 已完成 `docker-compose`（MySQL + Redis）
- 已完成后端连接串配置与联通验证
- 已完成一键启动命令与 README
- 已完成联调验收：
  - 认证流程
  - 创建订单与订单列表
  - 支付流程（含签名回调）
  - 跑腿员接单与送达
  - 双端状态一致性
  - 失败分支（支付失败、取消订单、无人接单）
- 已准备 3 条演示数据与 3 分钟演示路径
- 已完成最终自检并记录问题

## 3. V1 未完成项（纳入后续迭代）

- 测试链路中的 `httpx` 废弃告警治理（需配合 FastAPI/Starlette 升级窗口）
- 真实支付渠道生产级接入（当前以最小方案和模拟演示为主）
- 管理后台能力（审核、运营、财务）未纳入 V1

## 4. 演示可用性结论

V1 已达到“可演示、可走通、可讲解”的验收标准，可用于课堂展示、项目初评和下一阶段立项评审。
