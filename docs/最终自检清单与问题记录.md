## 1. 自检结论

- 结论：**通过（可演示）**
- 范围：用户端、跑腿员端、后端核心接口、支付回调、关键失败分支
- 演示可用性：满足“3 分钟主链路 + 失败分支”演示要求

## 2. 自检清单

### 2.1 支付闭环

- ✅ 支持下单 -> 收银台 -> 支付结果（成功/失败）
- ✅ 支付失败后可回到待支付并重试
- ✅ 后端支付回调包含签名校验与幂等处理

### 2.2 订单状态一致性

- ✅ 用户端与跑腿员端状态一致（`pending_take -> accepted -> completed`）
- ✅ 跑腿员接单后订单从大厅移除
- ✅ 订单详情与订单列表状态字段一致

### 2.3 关键页面动作反馈

- ✅ 关键动作具备明确主按钮（提交并支付、立即支付、确认送达）
- ✅ 关键链路具备反馈页（支付成功/失败）
- ✅ 列表与消息页接入 loading/empty/error 状态组件

### 2.4 失败分支覆盖

- ✅ 支付失败：订单保持 `pending_pay`，支付单为 `failed`
- ✅ 用户取消订单：状态变更为 `cancelled`
- ✅ 无人接单：支付成功后状态为 `pending_take`，仍在接单大厅

### 2.5 接口与环境

- ✅ OpenAPI 可访问（`/docs`、`/redoc`、`/openapi.json`）
- ✅ MySQL 连接串可联通并可完成 SQL 初始化
- ✅ 一键启动命令与 README 已补齐
